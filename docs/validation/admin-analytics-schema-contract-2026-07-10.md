# Analytics events schema contract — 2026-07-10

This evidence record freezes the read-only Vistaire catalog observation supplied for the isolated data task. No production DDL or event-row mutation was performed.

- Table owner: `postgres`; RLS enabled, not forced.
- Exactly 16 columns: UUID `id` (PK, `gen_random_uuid()`), required UUID `restaurant_id`, nullable UUID `menu_id`/`dish_id`, required text `session_id`/`event_name`, required text `source` defaulting to `demo`, nullable text dimensions (`dish_slug`, `category_slug`, `search_query`, `filter_name`, `cta_name`), nullable JSONB `viewport`, nullable text `user_agent`, required JSONB `metadata` defaulting to `{}`, and required timestamptz `created_at` defaulting to `now()`.
- Six constraints: primary key; restaurant FK `ON DELETE CASCADE`; menu and dish FKs `ON DELETE SET NULL`; event-name and source checks.
- Eight live non-PK indexes are frozen exactly: category slug, dish id, dish slug, menu+created, event name, restaurant+created, search query, and session. The migration adds the compatible dashboard scope index `(restaurant_id, menu_id, source, created_at desc)`.
- Restrictive `vistaire_no_direct_public_access` policy applies to `anon` and `authenticated` for all commands with false predicates.
- Live `service_role` grants are preserved exactly as `DELETE, INSERT, REFERENCES, SELECT, TRIGGER, TRUNCATE, UPDATE`; the migration never revokes them. Browser roles remain revoked.

The live event-name check contains exactly 11 values: `session_started`, `session_duration`, `menu_opened`, `category_viewed`, `dish_opened`, `dish_3d_clicked`, `dish_ar_clicked`, `search_used`, `filter_used`, `cta_clicked`, and `dashboard_demo_opened`.
